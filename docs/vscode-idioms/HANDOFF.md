## Step 2 — check what the cloud could not

The cloud verified in a harness and in code-server (VS Code in a browser).
Only the real editor can answer these; report each as ✓ / ✗ with a screenshot:

1. **Keys reach the webview?** With the tree focused (click its background):
   `F8` / `⇧F8` (next/previous problem), `⌘.` (opens the node menu), `Space`
   (fold the active goal), `⌘K ⌘0` / `⌘K ⌘J` (collapse / expand all). VS Code
   may consume `⌘.`, `F8` or the `⌘K` chord before the webview sees them. If
   one is swallowed, say which; the fallbacks are `⇧F10` and the strip's arrows.
2. **Squiggles** on a node with an error, a warning (e.g. an unused `simp`
   argument) and a Mathlib lint (`lean/ProofTreeLints.lean`): wave under the
   tactic text, three dots for the lint, hover shows the message.
3. **Theme inks** in the owner's own theme (light and dark): hypothesis names,
   `⊢`, case labels match the infoview's goal display directly above; menus,
   tooltips, toasts look like the editor's.
4. **Right-click** on a node opens Ramify's menu, not the browser's; right-click
   on the background is untouched.
5. Anything that looks off — a clipped icon, a misaligned baseline, a colour
   that is wrong in the owner's theme.
