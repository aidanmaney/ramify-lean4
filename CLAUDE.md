## What this is

A Lean 4 proof rendered as an interactive tree. Two data sources feed one React/d3-dag view:

```
1. Live infoview widget (the product):  cursor ──ProofTree.getProofTree RPC──▶ Proof ──proofToTree──▶ tree
2. Offline CLI (dev harness only):     proofs/*.lean ──ppharness──▶ NDJSON ──proofToTree──▶ tree
```

- `lean/` — dev Lake package (requires Mathlib so `import Mathlib` fixtures elaborate). `Ppharness.lean` wraps Paperproof's `BetterParser_Tree`; `Main.lean` is the CLI; `Ramify.lean` the widget (`@[server_rpc_method] ProofTree.getProofTree`, `@[widget_module] Ramify` — top level, not `ProofTree.Ramify`); `ProofTreeComments.lean` (comments/slots/calc/holes, `import Lean` only); `ProofTreeRecover.lean` (failed/term/calc-link/open-block recovery; the one file besides entry points allowed to import Paperproof types).
- `dist/` — the INSTALLABLE package (Paperproof + ProofWidgets only, `srcDir = "../lean"`, sources shared). `INSTALL.md` is its manual; `package.sh` builds it and the `.vsix`.
- `web/` — React + Vite + d3-dag. `ProofTreeView.tsx` = the shared source-agnostic view; `App.tsx` feeds NDJSON (harness); `widget.tsx` feeds RPC (infoview). Only `taggedRender.tsx` and `tacticTokens.tsx` may import infoview APIs.
- `ext/ramify/` — VS Code companion extension (gestures the infoview API can't do: lens, reveal, undo relay, theme colours/settings via `~/.proof-tree-companion/theme-colors.json`). Installed from the `.vsix`, never a symlink; `extension.js` edits reach the editor only via reinstall + window reload.
- `web/dist/proofTreeWidget.js` is TRACKED (Lean `include_str`s it; a fresh clone runs no npm). `lean/lakefile.toml` declares it an `input_file` wired via `needs` so `lake build` notices a JS-only change.

Fixture/demo files under `lean/` (none is a Lake target; several are deliberately broken): `ProofTreeTour.lean` (working guided demo), `ProofTreeExercises.lean`, `ProofTreeGoalsDemo.lean`, `ProofTreeGoals.lean`, `ProofTreeDiagnostics.lean`, `ProofTreeErrors.lean`, `ProofTreeTerms.lean`, `ProofTreeScratch.lean` (the user's live file, Mathlib), `ProofTreeDemo.lean` (big λ-calculus WIP). Corpus: `proofs/*.lean` → `web/public/sample.ndjson` (generated, never hand-edit).

## Commands and the working loop

```bash
./dev.sh              # build:widget → lake build Ramify → is the running file worker newer than the olean?
./dev.sh --check      # freshness only.  A stale worker = the editor is showing the OLD bundle:
                      # click "Restart File" in the infoview with a REAL click (AXPress does nothing), then re-check.
./dev.sh --all        # + package.sh (dist/ build, .vsix)
./gen.sh              # proofs/*.lean → web/public/sample.ndjson (after editing proofs/)
cd web && npm run typecheck && npm run lint     # no test runner; these plus the probes are the gate
cd web && npm run probe                         # lists probes
cd web && npm run probe -- counts               # fixture invariants for cuts/folds (expected numbers are MEASURED — a change is a finding)
cd web && npm run probe -- overlap              # ink-overlap sweep for ghost markers, 5 placements × combine
cd web && npm run probe -- order                # folding a goal never moves it among its siblings, 4 layouts
cd web && npm run probe -- hopgap               # the run below a hopped goal holds the axis break with line both sides
cd web && npm run probe -- fold odd_sums seed root   # ASCII tree with cuts applied (see fold.mjs header for the vocabulary)
cd web && npm run probe -- lsp ../lean/ProofTreeTour.lean 12 4 [--json] [--all]   # the LIVE server: real payload at a position
cd lean && lake exe cache get && lake build     # RE-RUN cache get after any `lake clean` (else Mathlib compiles for hours)
```

- **Probes** (`web/probe/`): `run.mjs` esbuild-bundles `lib.ts` (a barrel over the pure src modules) to `probe/lib.mjs` (git-ignored) and runs `probe/<name>.mjs`; `corpus.mjs` has the loaders/helpers (`records`, `tree`, `find`, `goalWithHyp`, `draw`, `structural`, `tally`). layout.ts measures text with a per-character fallback under node, so the whole engine runs offline.
- **Harness**: `npm run dev` (Vite; port from the preview logs), `http://localhost:5173/?stub-edit` (stubbed edit hooks: writes land in `window.__edits/__adds/__deletes`), `&cursor=<line>:<col>` (stubs the editor cursor; `window.__cursor(l,c)` moves it), `&cf-stub=`, `&cf-replay=`, `&no-ledger`. **`window.__ptw`** is the driver: `select(i)`, `which("odd_sums")`, `count()`, `nodes()`, `find(text)`, `goalWithHyp("key","gap")`, `breaks()`, `click(id,{alt,meta})`, `dblclick(id)`, `button("Zoom out",{alt:true})`, `background()`, `key("Escape")`.
- **The hidden preview pane fires no rAF/timeouts reliably and no native focus/scroll transitions**: use `setTimeout` not rAF in product code; in probes dispatch real `MouseEvent`s, take a `screenshot` first (the pane has no height until then), wait ~1.5 s for eased scrolls, and verify resizes with `resize_window` + a screenshot.
- **Widget-only data never rides NDJSON** (tagged goals, token infos, diagnostics, counterfactual, tacticEdits) — the harness cannot show it; the LSP probe is the only gate. The live server also differs from the CLI in ways that have bitten: `snap.msgLog` is EMPTY on the server (use `doc.collectCurrentDiagnostics`); `Elab.async` is ON there; initialise with `hasWidgets: true` and read messages via `toDiagnostic.message`.
- **Measuring inside the real infoview** (no devtools): a temporary effect that `showToast`s a `getBoundingClientRect`, read off a zoomed screenshot, throttled (an unthrottled one is React error #185), then stripped. The infoview runs at a fractional device-pixel ratio (retina × VS Code zoom); Chrome snaps border widths to device pixels, padding is not snapped.

## Standing rules

- **Never fork the vendored Paperproof parser.** Post-process its output (label fix-ups, sidecars, additive walks over `snap.infoTree`).
- **View identity and view state key on SOURCE facts** (declaration name, source position, tree path) — never mvarIds, which renumber per elaboration. `shapeKey` is the one deliberate mvarId user (a change DETECTOR). `remapIds` (layoutKey.ts) translates every id-holding view set across re-parses by tree path; `viewStash` keeps a departed proof's reading state under its `proofKey`.
- **Decompose syntax by KIND, never by argument index.**
- **`Lsp.Range` never crosses the wire** (its `end` field vs the client's `stop`); use `DeclRange`/start-stop pairs. `incoming` in widget.tsx rebuilds `Proof` field by field, so a new wire field is silently absent unless added there too — and some fields (`deleteSlots`) are deliberately left off and passed as siblings: a reader of an optional `Proof` field must take it as an argument with the field as fallback, or it works offline and does nothing in the widget.
- **Leave the author's text unfinished rather than complete it with something they did not choose** (calc gestures: one line per gesture, ask LHS/RHS separately, `by sorry` never `?_`, a leading `by` typed into a fill is de-duplicated but never supplied).
- **Measurer and renderer are paired** (`sizeOf`/`HypBlock`, `ghostSize`+`badgeWidth`/the ghost paint, `linkSpans`/link routing, wrap geometry, every overlay's inset): change one, change both; exported constants are shared, not copied.
- **No relayout on hover**; every relayout is anchored (`anchorOn`/`anchorAs`/the cursor node/the nearest-centre `[nodes]` anchor); the view must never move on its own — the user's most repeated complaint.
- **No setState in effects; render-called functions must not touch refs** (react-hooks/refs and the React Compiler lint are the gate — restructure, never disable).
- Toolchain **Lean v4.32.2**, Mathlib `v4.32.2`, Paperproof pinned by commit (upstream moved to the module system). `Main.lean` re-arms `enableInitializersExecution` per file (v4.32 clears it after every `importModules`).
- Commit only when asked; "commit" means on `main`.

## Facts the code depends on (grep the record for the why)

**Wire.** Paperproof's `ProofStep`/`GoalInfo`/`Hypothesis` are mirrored in `web/src/paperproof.ts`; `ProofStep` cannot grow, so per-step data rides SIDECARS keyed by `position.start` (`recovered`, `tacticEdits`, `tacticSlots`, `deleteSlots`, `comments`, `calcChains`, `holes`, `openBlock`, `diagnostics`, `declHeader`…). Plain data ships on BOTH wires so probes can run offline; `WithRpcRef` data (tagged goals, token infos) is widget-only. Positions include trailing trivia; `tacticEdits` carry the tight range and verbatim text. The recovery parser emits Result-shaped steps/goals so nothing downstream special-cases them.

**Tree (`proofToTree.ts`).** Each step is `goalBefore → tactic → goalsAfter ++ spawnedGoals`; nodes in DFS preorder (layout and elide slot arithmetic rely on it); goal labels carry the `⊢ ` prefix; a goal node carries its PRODUCER's position; `TreeNode.side` marks generated obligations (rw family only), `spawned` nested by-blocks; four context breadths (`used` default, `intro`, `diff`, `all`) + `hypGroup` (off by default = Lean's binder order); `goalIndex` keeps the print with fewest metavariables (mirrored server-side in `mvarOccurrences`); comments attributed by trivia containment, flags (`.fold .none .no-hyps .h#`) parsed BEFORE markdown cleanup; calc chains draw as a ledger with links as branches; term-justified links, failed tactics, term proofs and the open block come from `ProofTreeRecover.lean`.

**Cuts (`elide.ts`) — ONE hiding mechanism.** `ElideCut` is `fold` (goal-keyed: everything strictly below the goal; the goal stays, wearing `+`), `step` (tactic-keyed skip: the tactic plus what it opened beside its continuation, `continuationOf` — no longer what any gesture mints, see below), `band` (marquee set) or `combine` (⇉ runs). `applyElisions` transforms the `TreeNode[]` BEFORE the engine, minting a positionless MARKER node per cut (id = `cutId`); `disjointCuts` keeps cuts pairwise disjoint (bigger wins, loser stays stored); `pruneCuts`/`remapCut` carry them across re-parses. A goal's `−` is `goalCut`: in ⑃ wide every goal with children FOLDS; in the compact layouts a TRUNK goal (its producer's continuation) HOPS its consumer's step (the same cut ◌ on the tactic mints — `stepCut` is the one dispatch, `addCut` dedupes by `cutId`), any other goal folds — and so does a trunk goal whose consumer is a closing tactic, a ghost, or several nodes (user direction: EVERY goal with children carries the corner control, the root included; only a childless goal has none). ◌ on a LEAF tactic under a goal is that goal's fold (`stepElidable` admits leaves; `stepCut` falls through to `goalCut`), so a branch shortens from its end by skips alone. ◎ focus is offered on a collapsed goal too and OPENS it (`focusOn` drops the goal's cut first). `.fold`/`.none`/`rflResidue` seed cuts through `cutsForTargets`/`sourceView`; `collapse all` = `outlineCuts` (a fold on every branch root); `expand all` clears cuts; `reset` re-seeds; the cursor PEEKS seeded cuts open (`peekable`, tactic members' positions only). **Reading down a proof.** A trunk goal's `−` is a HOP (`{kind:"hop", id, steps}`): its consuming step and what that step opened beside the continuation go; the continuation goal STAYS (the next tactic keeps the goal it solves — a tactic without its goal has no context), re-parented onto the hopped goal, which wears `+N`; chained hops drop only the goals BETWEEN. The link out of a hopped goal carries `HopBreak`, a graph-style axis break (two slanted strokes across a cut in the line) at the MIDPOINT of a run the layout widens to `TRUNK_GAP_HOP` (34, against the step gap's 14) so the line visibly picks up again below it — paint only, never a node, and not gated by `linkMarks`, which now defaults OFF everywhere (companion, Lean, client). Beside it, to its right, the CAPTION (`hopCaption`/`tacticKeyword` in elide.ts, `HOP_CAPTION_GAP`/`hopCaptionWidth` in layout.ts): the `.none` note in italics, else the head word of each hidden tactic in source order, ` · `-joined, three elements with `…` as the third (`have · intro · …`); the axis-break label idiom, and what says WHAT went now that no ghost does. Caption and strokes click like the corner `+N` and carry the same `<title>`; nothing reserves room for them, so `probe hopgap` and `probe overlap` model the caption's rect against every node box. ◌ on ANY step is that same hop from its drawn parent goal (`stepCut` → `hopForStep`), so skip and collapse reach one position with one look; where no hop can be read (a closing tactic, a split with no continuation) the goal above FOLDS instead — `goalCut`'s own answer, asked not re-derived — and a calc-chain step, which hangs off the ledger tactic rather than a goal, is the one place ◌ still mints a ghost. A ◌ on the step under a hop's KEPT goal extends that hop's `steps` (the goal's `+N` is the tally). A marquee swept down one straight trunk run is rewritten as the same hop (`hopForBand`, an exact member-set test); any other band keeps its marker. `coalesceCuts` runs on every cut write: once every node under a branch-root goal is a ghost, the pieces become that root's `fold` (`+N` over the whole branch), so finishing a side-tree from the bottom never sends the reader back up; only BRANCH ROOTS (decided on the base tree) coalesce — a hop's kept goal is a continuation and must not. **Two standard idioms, one count field.** A FOLD mints NO marker: `applyElisions` stamps the goal with `folded {tactics, parts, note}` and the goal itself is the reduced node — its corner reads `+N` (N hidden tactics) where `−` stood; click restores (the outliner / VS Code fold-badge idiom; holds in wide too). A SKIP (band, or the `step` shape a `.none` seed falls back to) mints a marker drawn as the tactic REDUCED IN PLACE: a dashed tactic-shaped box whose label is `tacticHead` (the label cut at the first ` : `/` := `/` at `/`, `/` with`, ≤ 26 chars, `…`) — or the `.none` note in italics — with a `+N` BADGE at its right edge for the further tactics it swallowed (`ghostSize`/`badgeWidth`, layout.ts; `isGhostNode` is the one predicate); links and their marks are the ordinary tactic ones; hovering lists the hidden tactics in the `<title>`. (The ghost for a single step went in 2026-09: the same position was reachable by ◌ on the step and `−` on the goal above, and drawing it two ways was the bug. What survives it is the break's caption.) Combined (⇉) markers keep their full box. The corner control sits TOP-RIGHT (user direction, after a try at the end of the top line); `sizeOf` reserves `CORNER_W` on the top line (`topLineWidth`) so `+40` never overprints it. A folded goal ranks on its swallowed tactics' positions (`ownPositions`, layout.ts — a goal alone carries only its producer's position, which sibling cases share, so a folded case changed places; `probe order` sweeps every goal × goal-keyed cut × layout for 0 moves). Every ghost wears a `+N` badge with N = every tactic inside it, the goal corner's reading (a single skipped step read `+0`, i.e. no plus to unfold with). `collapse all` computes `outlineCuts` over the BASE tree and REPLACES the cut list — over the drawn tree it missed branch roots hidden inside a standing `.none` ghost (17/3 against 14/4). **The author's voice.** A cut the SOURCE asked for is `seeded` (plus `seededBy: "none" | "fold" | "residue"`), set ONLY in `sourceView` and carried by `remapCut`/`pruneCuts`/`disjointCuts`/`coalesceCuts` (the coalesced fold is seeded iff every piece it absorbed was) but deliberately NOT by `cutId` — a reader's `−` on a seeded goal mints the same id, and `addCut` keeps the standing seed rather than replacing it with a plain cut. `applyElisions` stamps `folded.seeded`/`elidedCut.seeded`; seeded caption and ghost label wear a leading `§ ` (`SEED_MARK`, written INTO the label so `ghostSize`/`hopCaptionWidth` measure it) in italics, and a seeded corner `+N` is italic in `--ptw-comment` ink rather than the node's stroke; `seedTitle` names the flag in the `<title>`. Measured baselines live in `web/probe/counts.mjs`.

**Marks (`tour.ts`; the reader's word is MARK — no user-facing string says "tour" or "stop", while the code keeps `tour*`).** An ordered reading of one proof, the model being VS Code's CodeTour crossed with vim marks. A `.mark` flag in a step's comment (parsed in `parseFlags` beside `.fold`/`.none`, BEFORE markdown cleanup, and landing on `TreeNode.flags.mark` as `number | true`) makes that step an AUTHOR stop; `.mark 3` is an explicit rank, and explicit ranks sort ahead of every bare one (ties, and the bare ones, by source position then DFS index). The caption is the comment's first sentence (`firstSentence`, ≤ 80 chars with `…`) — the same text the strip shows — falling back to the node's label. Flags ride the COMMENTS SIDECAR, which is plain data on both wires (`stableProofOf` carries `comments`), so `incoming` in widget.tsx needs nothing new. The READER's stops are a `Set<string>` of node ids in view state, ordered by source position, carried across re-parses by `remapIds` and kept in `viewStash` under the proof key (session only, never localStorage). Gestures: the CORNER NUB alone (user direction, 2026-09-08 — the hover bar's `⚑` is GONE, the corner already offering both): plain click toggles a reader mark, ⌥-click writes `-- .mark` through `flagLine` where the node can take one (`markWritable`; no prompt — the author's words are theirs to type), and `stoppableHere` no longer feeds `hasBar`; `<` and `>` step (PUNCTUATION, so the no-single-letter-keys rule is not in play), and from NOT STARTED `>` takes the first stop, `<` the last; Esc clears the current stop (not the list) via a `layers` row between the prompts and the scopes. The jump PEEKS every cut covering the stop open (`tourPeek`, filtered out of the cut list exactly as the cursor's `peekKey` is) rather than dropping it — a reading must not destroy the reader's folds — then `anchorOn` + `accentNow` + `setSeek`, and toasts `2/5 · <caption>`. Paint: a `BADGE_H` rounded tab STRADDLING the box's top-left corner (`tourTabWidth`, layout.ts), comment ink for the author's stops and `SEQ_STROKE` for yours, filled for the stop being read; it reserves NOTHING, so `probe overlap` models its rect against every node box. EVERY tab CLICKS TO JUMP, the author's included (`goToTab` → `goToStopIn(tourStops, i)`; only stops in the reading wear a tab, so there is nowhere else to look), and ⌥-click on one of YOUR OWN takes the stop back off; titles "Mark N of M (temporary) — click to go, ⌥-click to remove" and "Mark N of M (source) — click to go", and `NodeGates.tourTab` (`"author" | "mine" | null`) is what tells the two rows apart in gestures.ts. The plain click on the nub therefore always means DROP. On a node with no stop, a QUICK-ADD NUB stands in the tab's own rect — the same pill, outline only, `strokeDasharray "2 2"` in `SEQ_STROKE` at 0.6 — drawn ONLY while the pointer is in the box's TOP-LEFT CORNER, not on every hover of the node (user direction, 2026-09-08: a reader hovering a node to read it should not meet the nub each time). The corner is a dedicated invisible REGION (`[data-ptw-nub]`, `fill="transparent"` + `pointerEvents="all"` — an unfilled rect is not hit-testable): the tab's rect grown by `NUB_SLACK` 8 on every side, so it reaches outside the box (a pointer arriving from outside lands on it without entering the node first) and inside it only as far as the tab's own height, clear of the first line's text. The region carries both the hover (`nubHoverId`, paint only — the node's `hoverId` and its bar answer to the box and the bar alone, as before the nub existed) and the click: plain `toggleMyStop`, ⌥ `writeMark`, `<title>` "Drop a mark here — ⌥-click writes `.mark` into the source". Paint inside the node's `<g>`: no relayout, and nothing new for `probe overlap` to model (the nub occupies the rect the tab sweep already checks; the region is invisible and modelled nowhere). **There is no off mode, and no explicit `all`** (user direction, 2026-09-08): the state is TWO INDEPENDENT TOGGLES, `tourLists: {source, temp}` — an explicit `all` was a third thing to pick when the only question a reader ever asks is which sets are IN — and NOT HAVING STARTED is `tourAt === null` beside them. The list being read is the UNION of the enabled sets (`tourList` in tour.ts dispatches to `allStops` / `authorStops` / `myStops` / `[]`): a node carrying a `.mark` and one of yours appears once, as the author's. BOTH ARE ON where a proof arrives (the `tourFor`/`proofKey` block beside the seed); the reader's toggles stand thereafter, and a proof change sets `tourAt` null, never a toggle. both may be OFF (plain checkboxes; an empty reading greys the chevrons and draws no tabs), and ⌥-click on the item walks both → source → temp → none → both. Dropping a mark while the temporary list is off turns it ON (`toggleMyStop`; the reading restarts from a standing start, the view stays put) — a mark that did not show up read as a failure. Every list shares one comparator (`ranked`): the author's explicit ranks first, then source position then DFS index. Toggling either set restarts the reading from a standing start (`tourAt` null, `tourPeek` cleared) and TAKES ITS TABS WITH IT — only stops in the reading wear tabs, each in its own ink, so a marked proof shows its tabs on arrival. The status bar's fifth value item reads `Marks: –/5` (en dash = not started, `–/0` = empty) or `Marks: 2/5`, and `Marks: off` where BOTH lists are off — an OFF value, dimmed at opacity 0.6 through `BarValueItem.dim` exactly as the width readout dims at `full` — NO LIST NAME in the value, because the two extras SLOTS say it: `[tourLists.source, tourLists.temp]`, lit when the set is IN the reading rather than when it merely has stops (they look like switches, so they are). `values` reserves `["–/99", "99/99", "off"]`; `‹ ›` sit beside it (`BarValueItem.after`, measured inside both ghost forms), NO ACCENT, and the chevrons are `disabled` (0.35) while the union is empty, drawn by the same `glyph()` helper the ⚑ uses at `CHEVRON_PX` 18 in `TEXT_GLYPH_BOX_W` (measured: a guillemet inks 5.4px at the bar's 12px against the ⚑'s 7.65, and 14 only reaches 6.3). The panel is two CHECKBOX rows, `source (n)` and `temporary (n)` — the lists are NAMED by where a stop LIVES, the file's `.mark`s against this session's nub drops, while the code keeps `author`/`mine` — each toggling its set and leaving the panel open; ⌥-click on the bar item cycles both → source → temp → both. One empty message for every path (`<`, `>`, and the chevrons): "No marks in the lists that are on — the corner nub drops one". Toasts are "Mark dropped (⚑)" / "Mark removed" / "Marks: source + temporary | source | temporary | off"; the title when off is "Marks: off — both lists are off; click for the lists, ⌥-click cycles".

**Layout (`layout.ts`).** `createLayoutEngine(nodes, opts)` then `computeLayout(only?, focus?, compact?, sideBySide?, hide?, aside?)`; four modes (stacked default, spine, tracks, wide); source order is computed (`srcRank`, subtree-min, markers rank on their members); trunk goals resume the trunk, `side` obligations first in stacked; the aside modes float a tactic's comment strip and publish `trackFloor` before recursing; chips lane is reserved below pending goals; reflow re-wraps at a column budget (the ¶/Width setting, also the draggable seam in tracks); big comment strips clamp to 2 lines + affordance; `bandTopH`/`inkExtent` are the ONE coding of a node's vertical ink — every render site reads them.

**Widget (`widget.tsx`).** The RPC re-fires on cursor AND `publishDiagnostics` (`docRev`); server-side `proofTreeCache` keyed `(uri, version, command start, diagnostics count)`; `stable` (plain data, swapped only when the proof TEXT changes and the cursor has been still `typingHoldMs`) vs `interactive` (ref-carrying, latest response); navigation = `proofId` changed AND cursor left `declRange`; the widget's own edits bypass the hold via a 3 s window. Counterfactual (`cf*`): while the cursor's line is broken the server re-elaborates with that line spliced to `sorry` and the client draws a dashed stub; the open block (`:= by` with nothing) is Part C of recovery, not cf. `useFrameOffset` sizes the frame to `calc(100vh − measured top)`; the frame measures a tick AFTER the widget mounts, so the first layout has NO padding (`PAD_X/PAD_Y` = 0) — the cursor-follow and seek effects wait for a real viewport, and the arrival centring cancels any in-flight follow (`cancelFollow`), else an animation started on the unpadded layout drags the centred tree out of the frame (Restart File showed a blank frame until ⛶; measured 2026-09-08); the status card and rail dodge the host's "Restart File" button by placement (`LANE_*` constants).

**Editing (widget only).** Double-click edits a tactic in place (overlay = the box's rect grown by `EDIT_STROKE/2`, padding-only inset, outline as inset box-shadow, box fill; empty commit cancels); comments edit the same way (empty commit deletes the line); completion from on-screen hyps/subterms/tactic names + the `completionNames` RPC; unicode abbreviations via `@leanprover/unicode-input`; frontier chips `+`/`sorry`/`calc`/`step`/`?_` on pending goals (`addSpec`, insertion column from `TacticEdit.tacticIndent`); delete arms then writes over a `TacticSlot` extent (`deleteEdit.ts`); flags are written by the marquee pill (`flagEdit.ts`, bottom-up patches, whole-line removal rule); undo/redo relay through the companion. All writes go through `ec.api.applyEdit`; the tree redraws off the next RPC.

**Diagnostics, tokens, tooltips.** Diagnostics ride the payload (`collectCurrentDiagnostics`), draw a ribbon on the node and the bar's pager item, reserve nothing. Tactic labels are coloured from the editor's own semantic-token pair plus `collectConstIdentTokens` (popup only) and numerals; the LABEL is the coordinate space (`alignInLabel` segments, `labelTokens` for prettifier-minted words); goal labels/hyps are `InteractiveCode` under a text-equality guard (mismatch → plain SVG, silently); the tactic diff (`diffInteractiveGoals`, `useAfter`) rides the producer's print. Colours come from the user's theme via the companion; VS Code's own scope table; bracket colours from the registry variables.

**Controls.** A status bar of words (`Layout: outline · Context: used · Comments: show · Width: full · eye(brief, merge, to cursor) · ↺ · ?` + diagnostics), one fixed height (`BAR_H` 26, items 20, glyph boxes fixed), progressive right-to-left compaction to glyphs measured off a hidden ghost, THREE PLACEMENTS decided from the frame and the ghost alone (`fit`): the card dodges the host's Restart-File button only while the lane beside it still holds the all-glyph row (`need(0)`) — below that it FILLS the frame between its own insets rather than clipping itself into the leftover strip (the reported two-glyph collapse on a ~280px panel) — and where a centred card clears that lane by a whole reserve it is CENTRED, the right anchor's constant-gap reason holding only while the card is beside the button;
