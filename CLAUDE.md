## What this is

A Lean 4 proof rendered as an interactive tree. Two data sources feed one React/d3-dag view:

```
1. Live infoview widget (the product):  cursor ──ProofTree.getProofTree RPC──▶ Proof ──proofToTree──▶ tree
2. Offline CLI (dev harness only):     proofs/*.lean ──ppharness──▶ NDJSON ──proofToTree──▶ tree
```

- `lean/` — dev Lake package (requires Mathlib so `import Mathlib` fixtures elaborate). `Ppharness.lean` wraps Paperproof's `BetterParser_Tree`; `Main.lean` is the CLI; `Ramify.lean` the widget (`@[server_rpc_method] ProofTree.getProofTree`, `@[widget_module] Ramify` — top level, not `ProofTree.Ramify`); `ProofTreeComments.lean` (comments/slots/calc/holes, `import Lean` only); `ProofTreeRecover.lean` (failed/term/calc-link/open-block recovery; the one file besides entry points allowed to import Paperproof types).
- `dist/` — the INSTALLABLE package (Paperproof + ProofWidgets only, `srcDir = "../lean"`, sources shared). `INSTALL.md` is its manual; `package.sh` builds it and the `.vsix`.
- `web/` — React + Vite + d3-dag. `ProofTreeView.tsx` = the shared source-agnostic view; `App.tsx` feeds NDJSON (harness); `widget.tsx` feeds RPC (infoview). Only `taggedRender.tsx` and `tacticTokens.tsx` may import infoview APIs.
- `ext/ramify/` — VS Code companion extension (gestures the infoview API can't do: lens, reveal, undo relay, theme colours/settings via `~/.proof-tree-companion/theme-colors.json`). Installed from the `.vsix`, never a symlink; `extension.js` edits reach the editor only via reinstall + window reload.
- `web/dist/proofTreeWidget.js` is TRACKED (Lean `include_str`s it; a fresh clone runs no npm). `lean/lakefile.toml` declares it an `input_file` wired via `needs` so `lake build` notices a JS-only change.

Fixture/demo files under `lean/` (none is a Lake target; several are deliberately broken): `ProofTreeTour.lean` (working guided demo), `ProofTreeExercises.lean`, `ProofTreeGoalsDemo.lean`, `ProofTreeGoals.lean`, `ProofTreeDiagnostics.lean`, `ProofTreeErrors.lean`, `ProofTreeTerms.lean`, `ProofTreeScratch.lean` (the user's live file, Mathlib), `ProofTreeRestructure.lean` (D3/D5) and `ProofTreeLints.lean` (D4, one theorem per linter) — the two fixtures that `import Ramify`, which is what registers the RPCs the LSP probe calls, `ProofTreeDemo.lean` (big λ-calculus WIP). Corpus: `proofs/*.lean` → `web/public/sample.ndjson` (generated, never hand-edit).

## Commands and the working loop

```bash
./dev.sh              # build:widget → lake build Ramify → is the running file worker newer than the olean?
./dev.sh --check      # freshness only.  A stale worker = the editor is showing the OLD bundle:
                      # click "Restart File" in the infoview with a REAL click (AXPress does nothing), then re-check.
./dev.sh --all        # + package.sh (dist/ build, .vsix)
./gen.sh [--no-traces] [--no-lint]  # proofs/*.lean → web/public/sample.ndjson (B4 traces and D4 lints both ON; --lint is free, the corpus has 0 lints)
cd web && npm run typecheck && npm run lint     # no test runner; these plus the probes are the gate
cd web && npm run probe                         # lists probes
cd web && npm run probe -- counts               # fixture invariants for cuts/folds (expected numbers are MEASURED — a change is a finding)
cd web && npm run probe -- narrate [--print]    # template coverage + the residue (pinned at 244/244, residue 0); --print narrates odd_sums
cd web && npm run probe -- overlap              # ink-overlap sweep for ghost markers, 5 placements × combine
cd web && npm run probe -- order                # a fold or a hop never moves its goal among its siblings, 4 layouts
cd web && npm run probe -- hopgap               # every hop (trunk and branch), 4 layouts: the break has line both sides; a fold has no link to break
cd web && npm run probe -- rewrite [--declines]  # D1/D2/D3/D5: which restructurings are OFFERED over the corpus
cd web && npm run probe -- eval [--verbose]      # D6: the readability table + the infinitude_of_primes pair + the 5-moves fraction (4/5)
                      # eval ELABORATES lean/ProofTreeTour.lean and lean/ProofTreeScratch.lean into
                      # probe/eval-extra.ndjson (git-ignored, ~20s, cached on mtime) — gen.sh is untouched
cd web && npm run probe -- fold odd_sums seed root   # ASCII tree with cuts applied (see fold.mjs header; `skip:<tactic>` is ◌)
cd web && npm run probe -- lsp ../lean/ProofTreeTour.lean 12 4 [--json] [--all]   # the LIVE server: real payload at a position
cd web && npm run probe -- lsp ../lean/ProofTreeLints.lean 35 2 --lint          # D4: every lint, its node, its fix, checkRewrite's verdict
cd web && npm run probe -- lsp ../lean/ProofTreeScratch.lean 0 0 --all --edits  # the tacticEdits/deleteSlots tight-range invariant
cd lean && lake exe cache get && lake build     # RE-RUN cache get after any `lake clean` (else Mathlib compiles for hours)
```

- **Probes** (`web/probe/`): `run.mjs` esbuild-bundles `lib.ts` (a barrel over the pure src modules) to `probe/lib.mjs` (git-ignored) and runs `probe/<name>.mjs`; `corpus.mjs` has the loaders/helpers (`records`, `tree`, `find`, `goalWithHyp`, `draw`, `structural`, `tally`). layout.ts measures text with a per-character fallback under node, so the whole engine runs offline.
- **Harness**: `npm run dev` (Vite; port from the preview logs), `http://localhost:5173/?stub-edit` (stubbed edit hooks: writes land in `window.__edits/__adds/__deletes`), `&cursor=<line>:<col>` (stubs the editor cursor; `window.__cursor(l,c)` moves it), `&cf-stub=`, `&cf-replay=`, `&no-ledger`, `&trace-stub` (B4 without a server: `onTrace` answers from the NDJSON's own traces; `window.__traces` records the asks). **`window.__ptw`** is the driver: `select(i)`, `which("odd_sums")`, `count()`, `nodes()`, `find(text)`, `goalWithHyp("key","gap")`, `breaks()`, `click(id,{alt,meta})`, `dblclick(id)`, `button("Zoom out",{alt:true})`, `background()`, `key("Escape")`.
- **The hidden preview pane fires no rAF/timeouts reliably and no native focus/scroll transitions**: use `setTimeout` not rAF in product code; in probes dispatch real `MouseEvent`s, take a `screenshot` first (the pane has no height until then), wait ~1.5 s for eased scrolls, and verify resizes with `resize_window` + a screenshot.
- **Widget-only data never rides NDJSON** (tagged goals, token infos, diagnostics, counterfactual, tacticEdits) — the harness cannot show it; the LSP probe is the only gate. The live server also differs from the CLI in ways that have bitten: `snap.msgLog` is EMPTY on the server (use `doc.collectCurrentDiagnostics`); `Elab.async` is ON there; initialise with `hasWidgets: true` and read messages via `toDiagnostic.message`.
- **Measuring inside the real infoview** (no devtools): a temporary effect that `showToast`s a `getBoundingClientRect`, read off a zoomed screenshot, throttled (an unthrottled one is React error #185), then stripped. The infoview runs at a fractional device-pixel ratio (retina × VS Code zoom); Chrome snaps border widths to device pixels, padding is not snapped.

## Standing rules

- **Forking the vendored Paperproof parser is ALLOWED** (user direction, 2026-09-09 — the earlier "never fork" rule is struck). Post-processing (sidecars, additive walks over `snap.infoTree`) stays the cheap first choice, but where the harvest itself is the limit, change `BetterParser` in the tree (vendor it under `lean/` rather than patching `.lake/packages/`) and record what moved from upstream.
- **View identity and view state key on SOURCE facts** (declaration name, source position, tree path) — never mvarIds, which renumber per elaboration. `shapeKey` is the one deliberate mvarId user (a change DETECTOR). `remapIds` (layoutKey.ts) translates every id-holding view set across re-parses by tree path; `viewStash` keeps a departed proof's reading state under its `proofKey`.
- **Decompose syntax by KIND, never by argument index.**
- **`Lsp.Range` never crosses the wire** (its `end` field vs the client's `stop`); use `DeclRange`/start-stop pairs. `incoming` in widget.tsx rebuilds `Proof` field by field, so a new wire field is silently absent unless added there too — and some fields (`deleteSlots`) are deliberately left off and passed as siblings: a reader of an optional `Proof` field must take it as an argument with the field as fallback, or it works offline and does nothing in the widget.
- **Leave the author's text unfinished rather than complete it with something they did not choose** (calc gestures: one line per gesture, ask LHS/RHS separately, `by sorry` never `?_`, a leading `by` typed into a fill is de-duplicated but never supplied).
- **Measurer and renderer are paired** (`sizeOf`/`HypBlock`, `ghostSize`+`badgeWidth`/the ghost paint, `linkSpans`/link routing, wrap geometry, every overlay's inset): change one, change both; exported constants are shared, not copied.
- **No relayout on hover**; every relayout is anchored (`anchorOn`/`anchorAs`/the cursor node/the nearest-centre `[nodes]` anchor); the view must never move on its own — the user's most repeated complaint.
- **No setState in effects; render-called functions must not touch refs** (react-hooks/refs and the React Compiler lint are the gate — restructure, never disable).
- Toolchain **Lean v4.32.2**, Mathlib `v4.32.2`, Paperproof pinned by commit (upstream moved to the module system). `Main.lean` re-arms `enableInitializersExecution` per file (v4.32 clears it after every `importModules`).
- Commit only when asked; "commit" means on `main`.

## Facts the code depends on (grep the record for the why)

**Wire.** Paperproof's `ProofStep`/`GoalInfo`/`Hypothesis` are mirrored in `web/src/paperproof.ts`; `ProofStep` cannot grow, so per-step data rides SIDECARS keyed by `position.start` (`recovered`, `termLedgers`, `tacticEdits`, `tacticSlots`, `deleteSlots`, `comments`, `calcChains`, `holes`, `openBlock`, `diagnostics`, `declHeader`, `hypOrigins`, `haveUses`, `lemmaRefs`, `automationTraces`, `latex`, `lints`…). Plain data ships on BOTH wires so probes can run offline; `WithRpcRef` data (tagged goals, token infos) is widget-only. Positions include trailing trivia; `tacticEdits` carry the tight range and verbatim text — and a step whose MACRO expands to nested tactics (`intro h h2` → `intro h; intro h2`) is harvested at the inner node's range, so the edit is WIDENED to the `deleteSlots` slot that starts at the same place, but only where the slot's own text equals the step's label (that test is what admits `intro h h2` and declines `induction … with`'s whole block and a `<;>` combinator; `surfaceTacticRange` must NOT be loosened to do it — colouring wants the smallest container. `probe lsp … --edits` is the invariant; measured 0 short over the Tour and Scratch, and the corpus's only prefix truncations were 3 multi-binder `intro`s). The recovery parser emits Result-shaped steps/goals so nothing downstream special-cases them. **B4 automation traces** (`AutomationTrace {stepStart, tactic, kind, suggestion?, lemmas}`, kind `lemmas`/`opaque`/`failed`) are what `simp`/`grind`/`aesop` actually used, read back from core's own `?` forms — `simp?`, `simp_all?`, `grind?`, `aesop?` all exist in v4.32.2 and `grind?` says "Try **these**:" with `!`-prefixed names; `omega`/`linarith`/`ring`/`norm_num`/`decide`/`positivity` have no `?` form and get `opaque` with NO elaboration. ALL SITES IN A DECLARATION ARE REWRITTEN AT ONCE, so one re-elaboration answers for the whole proof (a `?` form behaves exactly as the bare one; the per-step splice would pay a Mathlib elaboration per `simp`). `reElabDecl` (Ramify.lean) is the seam `computeCf` and the traces share (`needInfoTree` is cf's only extra). The CLI's second pass MUST take the HEADER environment — `finalEnv` reports nothing but "has already been declared". Plain data on BOTH wires: `gen.sh` computes them (ON by default, `--no-traces` to skip; measured +3.9s on 167s for the corpus) and the widget gets them from `ProofTree.getAutomationTrace {pos, stepStart?}` ON DEMAND, cached `(uri, version, decl start)`, held in widget.tsx state keyed on `proofId` and passed to the view as a SIBLING. `applyTraces` (trace.ts) mints one positionless dashed leaf per lemma onto the DRAWN tree AFTER `applyElisions`, and `treeIdx` filters trace leaves out — elide.ts must not see them, or a closing `simp` with its trace open would stop being a leaf and the goal above would hop where it folded. Ids are `trace:<line>:<char>:<i>`. `lemmaRefs` (B3) is the per-step premise library — every constant a step's tactic text names, with `findDocString?`'s raw markdown and the `ConstantInfo` kind — harvested by `constIdentNodes`, the SAME predicate `collectConstIdentTokens` paints `const`-coloured (one predicate, so the colouring and the list cannot drift), and attributed to the INNERMOST containing step, since tactic ranges nest and a lemma inside a nested `by` is the inner step's alone; local hypotheses are fvars and never appear. **D1 `haveUses`** (`{stepStart, name, users: Lsp.Position[]}`) is `hypOrigins` (B2) composed with Paperproof's `tacticDependsOn`: for every `have`/`obtain`-introduced hypothesis, the steps the elaborator says read it. Plain data on both wires, emitted non-empty only; restricted to `have`/`obtain` because what `intro`/`by_cases`/`rintro` bind is the shape of the proof and nothing offers to inline it, and an EMPTY `users` is emitted (a `have` nothing uses is the finding). It is NOT a syntactic occurrence count — `omega` reads a hypothesis from the context and names it nowhere — which is why the inline move requires BOTH a single use and a single written occurrence. `TreeNode.uses {name, count, users: nodeIds}`; `count` is the elaborator's number and does not shrink when a cut hides a user. **D4 `lints`** (`Lint {start, stop, linter, message}`) are MATHLIB'S OWN linters, run by the elaborator and never reimplemented: `reElabDecl` gained an `opts` parameter and `ProofTree.lintDecl {pos}` re-elaborates the declaration once under `ProofTree.withLinters`, lazy and cached `(uri, version, decl start)` (measured 8–27 ms). The set is EXPLICIT — the tactic-level half of `mathlibStandardSet` plus `unusedTactic` and `haveLet`, which Mathlib leaves off — because every FILE-level linter (`style.header`, `style.longFile`, `style.missingEnd`, `minImports`…) would answer about a file that does not exist. The linter's NAME is read off the message's TAG, and the guard is `severity == .warning` + a matching tag and NOT `isLinterMessage` (Mathlib's `logLint0Disable`, which every `Nat`-valued linter uses, never adds core's tag — it would have dropped `haveLet`). `Elab.async` must be OFF or `runLintersAsync` posts the linters to a snapshot task this call never sees; `reElabDecl` already forces it. Plain data on both wires: `gen.sh` runs `ppharness --lint` by default (the linters ride the one elaboration the CLI already does — 176.5s → 173.0s, inside the noise) and the corpus is BYTE-IDENTICAL with it on, because `proofs/` has 0 lints over 34 records, which is the finding. `lean/ProofTreeLints.lean` is the live fixture, one theorem per linter. **C1 `latex`** (`LatexGoal {goalId, tex}`, keyed on the GOAL id because it describes a print, not a step) is a SEAM ONLY and is ALWAYS EMPTY: kmill/LeanTeX does not build against v4.32.2 (three incompatibilities — `String.split` returning `Std.Iter String.Slice` twice, and `aux_def`'s now-mandatory visibility three times; the fork `must-show-your-work/LeanTeX@779ac83` carries exactly that fix, and LeanTeX-Mathlib compiles against Mathlib v4.32.2 with deprecation warnings only). Both wires carry the field (`stableProofOf` included), the reading panel's `goals as TeX` row is drawn DISABLED with the reason in its title, KaTeX is NOT bundled, and `dist/` takes no new dependency. What the printer emits, and why half of it reads worse than Lean's own print, is in the 2026-09-09 record entry — read it before taking the bump.

**Tree (`proofToTree.ts`).** Each step is `goalBefore → tactic → goalsAfter ++ spawnedGoals`; nodes in DFS preorder (layout and elide slot arithmetic rely on it); goal labels carry the `⊢ ` prefix; a goal node carries its PRODUCER's position; `TreeNode.side` marks generated obligations (rw family only — decided by B5's `branch.form === "rewrite"`, not by a label regex), `spawned` nested by-blocks; four context breadths (`used` default, `intro`, `diff`, `all`) + `hypGroup` (off by default = Lean's binder order); `goalIndex` keeps the print with fewest metavariables (mirrored server-side in `mvarOccurrences`); comments attributed by trivia containment, flags (`.fold .none .no-hyps .h#`) parsed BEFORE markdown cleanup; calc chains draw as a ledger with links as branches; term-justified links, failed tactics, term proofs and the open block come from `ProofTreeRecover.lean`, and so does PART E (`recoverTermInStep`), term-level structure INSIDE a tactic: for `exact`/`refine`/`refine'`/`apply` only, and only where the term is STRUCTURED (an `⟨…⟩`, itself or inside a parenthesis or as an argument of an application — `exact foo a b` stays a leaf), every component gets its `TermInfo.expectedType?` as a goal GRAFTED onto the harvested step (the `recoverCalcLinks` seam) with `walkTerm` run below it, stamped `recovered: "subterm"`. Three guards, each a component that is already somewhere else or says nothing: a hole (`?_`/`_`) is the tactic's own goal, a component CONTAINING a harvested step is the harvest's (`⟨by simp, rfl⟩` grafts the by-block's root ONCE, as Part B's leaf already did), and a DATA component is not an argument (`Meta.isProp` is the gate — `refine ⟨2 * k * k, ?_⟩` grafts nothing). `walkTerm` gained the same `anonymousCtor` case, so term-mode proofs decompose too. **The components draw INLINE AS A LEDGER, the calc idiom exactly** (user direction 2026-09-09: "should inline like calc blocks since they're related") — ONE mechanism, `LedgerRow[]` on a `ledger:<line>:<char>` node, so the node, the row click (`chainOpen`), the layout (`ledgerSize`, no trunk child) and the paint are shared and the RENDERER BRANCHES NOWHERE. What differs is only where the rows come from: a chain threads them out of `spineRelation` (head row + `hiddenLhs` relation column), while a constructor has no relation to thread, so the server names the components in `termLedgers` (`{tacticStart, kind: "ctor", rows: [{goalId, start, stop}]}`, a per-step sidecar, plain data on BOTH wires) and `ctorLedgerFor` reads each row's TEXT off the goal, as `ledgerFor` does. `TreeNode.ledgerKind` (`"calc" | "ctor"`) is stamped on both the host tactic and the ledger node and is the ONLY thing anything downstream branches on (three places: `narrateFamily`, `runnable` in rewrite.ts, `blocked` in `combineRuns`). Calc-only behaviour is kept behind `calcLed`: the label `calc` stands for its chain while a constructor's tactic keeps its own text and its brief-mode elision; `chain` stays a calc flag. Below TWO rows nothing is minted — one component is better served by the branch box it had — so `⟨0, Or.inl rfl⟩` and `refine ⟨p, hp, ?_⟩` are unchanged; a `?_` continuation is not a row and keeps the trunk. Measured 2026-09-09 (`gen.sh` corpus, six ledgers: odd_sums 4 rows, euclid ×2 and multiline ×2 at 2, wrap 6): odd_sums 70→75 nodes, root hop 60, goal-after-key 73, succ fold 68, parity hop 49, collapse-all 19 drawn with 4 folded goals (the component goals are no longer branch roots, so nothing folds them — the calc ledger's standing behaviour); corpus-wide context lines with provenance 395→409. The lens strips subterm steps AND their grafts (widget.tsx `lensGoals`) — several share the `exact`'s line and would overwrite its `∎`. **B2, hypothesis provenance**: `hypOrigins` (a sidecar, plain data on BOTH wires, `ProofTree.hypOrigins` in ProofTreeRecover.lean) is a pure post-pass over the FINAL steps in source order — an fvarId in `goalsAfter ++ spawnedGoals` and absent from `goalBefore.hyps` was introduced by that step, FIRST WRITER WINS, so `rw … at h` (which re-mints `h`) is the origin of the hypothesis it produced. The declaration's own binders sit in the root `goalBefore` and so get NO entry: "from the statement" is said by silence. `proofToTree` resolves each origin's position to the introducing TACTIC NODE's id and stamps `HypLine.origin`/`originText`/`originLine`; matching is BY ID ALONE (a username fallback was written, measured, and removed — it fired twice in 1300 context lines and was wrong both times), and layout's wrap carries all three onto every wrapped piece. **B5, case/branch semantics**: `branches` (a sidecar, plain data on BOTH wires, `ProofTree.branches` in ProofTreeRecover.lean) decodes each branching step from its SYNTAX KIND — `induction`, `cases`, `rcases`, `obtain`, `rintro`, `by_cases`, `constructor`, `refine`, `match`, `split`, `interval_cases`, `fin_cases`, `rewrite` — into `{stepStart, form, on, withAlts, arms}`, each arm `{tag, binders, pattern, goalId}` in SOURCE order. Tags come from the elaborator, never the text: `induction`/`cases` from the `with | … =>` alternatives when the author wrote them (which is also what makes a `using` eliminator's own tags right) and otherwise from the inductive's `ctors` in declaration order; `constructor` from the target STRUCTURE's fields (`And` → `left`/`right`, `Iff` → `mp`/`mpr`; a non-structure inductive does not split and gets no arms); `by_cases` is `pos`/`neg`; `refine` takes a named hole's name; `rcases`/`obtain`/`rintro` resolve POSITIONALLY (where Lean itself is) and ADOPT the goal's tag. **Only ORIGINAL syntax counts** — `have … := by`, `by_contra` and `exfalso` all EXPAND to `refine` and the expansion inherits the source range, so a kind test alone gave a `have` a branch it never wrote (`.original` head info is the guard, the same one `constIdentNodes` uses). `arms := #[]` means the form was recognised and its arms were NOT (`match`, `split`, a nested `rcases` alternation such as `obtain ⟨k, hk | hk⟩`), and every client fallback keys on that. Client: `TreeNode.branch` on the tactic, `TreeNode.arm` on each child goal, `shapeSource` (`"branch" | "regex" | "none"`, probe-facing — 0 `regex` over the corpus). The retired regexes are `MAIN_FIRST_RE` (now `form === "rewrite"`, which rides EVERY step a multi-rule `rw` covers), `addSpecFor`'s `label.endsWith("with")` (now `withAlts`), and briefLabel's `^constructor`/`^(rcases|cases)` head tests (now `form`, with a LEXICAL head-word scan for the offsets); each keeps its old text test as the fallback where no branch reached the step. The case badge is GROWN, never minted — `succ k ih`, `inl ⟨k, hk⟩`, `pos hn` — so no goal gains chrome it did not have and `caseSize` measures the longer string it is handed. Child order follows the arms only on FULL coverage; measured 2026-09-09: 0 records moved, node counts unchanged.

**Narration (`narrate.ts`, C2/C3).** Pure and offline-probeable. `narrateStep(node, ctx)` writes ONE templated line per tactic KIND, dispatched on B5's `branch.form` FIRST and the head word second — never an argument index. It reads B2 `hypOrigins` (a step's new hyps are the child goal's `HypLine`s whose `origin` is this step: `intro`/`have`/`let`/`by_contra`), B3 `lemmas` (the principal one chosen by `ConstantInfo` KIND, theorem/axiom first, plus the docstring's first sentence), B4 `trace` ("simp used a, b"), B5 `branch` (discriminant, arm tags and binders; where `arms` is empty the patterns come off the produced GOALS' own `arm`), the recovery kind, and the calc ledger — which hangs off the goal the `calc` step opened, not off the step. `summarize(nodes)` folds a node's line with its children's by the tree's structure (spawned obligations → "(proved by: …)", splits → "Case zero: …; Case succ: …", runs → "…; then …"), bounded at ONE level with deeper subtrees as "(3 more steps)" and clipped at 260 chars. `applyNarration(drawn, base)` writes the lines onto `comment`, prefixed `∴ ` (`NARRATE_MARK`, written INTO the string so `commentSize` measures what is painted — the `SEED_MARK` idiom); the author's comment always wins, ghosts and trace leaves get none, and goals get none EXCEPT a folded one, whose strip is the summary of what its `+N` hides (a fold → the goal's subtree summary; a hop → composed from the parts the cut names). It reaches the LAYOUT ENGINE ONLY (`narratedNodes` beside `treeNodes`), so no gesture ever offers to edit, hide or delete a generated line. Coverage is pinned by `probe narrate` (244/244 tactic nodes, residue 0; `--print` prints odd_sums as a narrated outline), and `probe overlap` sweeps both strip modes. **C4 — optional POLISH.** The `polish` row in the reading options (off, and disabled with a title where there is no companion or no key) sends the templated lines — never the author's own comments — through the companion to be REWRITTEN, and the answer stands in the strip wearing `≈ ` (`POLISH_MARK`, written into the string like every other mark). The prompt is the constrained one every informalization paper reports as best: rewrite, keep every symbol and name, add no facts, one line per input in the same order, JSON out, with the states as context only. `polishLines(base, drawn)` builds the request out of `narrationFor`'s own map; answers are cached PER SENTENCE (`polishCacheKey` = node id + its template), so a cut — which changes which nodes are drawn and nothing else — never re-asks for a line already in hand, and a line that failed or came back empty stays marked so nothing retries on its own (`askedRef`); `polishKey(lines)` is only the effect's dependency. The setting is the DEFAULT and the row is a session OVERRIDE (`polishOverride: boolean | null`) — a copy would need syncing from an effect when the companion's late answer arrives. **Cuts (`elide.ts`) — ONE hiding mechanism.** `ElideCut` is `fold` (goal-keyed: everything strictly below the goal; the goal stays, wearing `+`), `hop` (goal-keyed SKIP of the consuming step(s), keeping the continuation goal), `step` (tactic-keyed ghost: the tactic plus what it opened beside its continuation, `continuationOf` — left only for a `.none` on a split and a step under a tactic, see below), `band` (marquee set) or `combine` (⇉ runs). `applyElisions` transforms the `TreeNode[]` BEFORE the engine, minting a positionless MARKER node per cut (id = `cutId`); `disjointCuts` keeps cuts pairwise disjoint (bigger wins, loser stays stored); `pruneCuts`/`remapCut` carry them across re-parses. **THE VERB DECIDES THE IDIOM, NOT THE GOAL'S POSITION** (user direction 2026-09-17: "while reading to the end I go for skip; while taking a high-level look I go for hide"). A goal's `−` is `goalCut` and it HIDES: every goal with children FOLDS, in every layout, trunk goals and the root included (on a trunk goal that is the rest of the proof — intended); only a childless goal has no corner control. ◌ on a step is `stepCut` and it SKIPS — offered (`stepElidable` asks `stepCut`, one door) only where the step has EXACTLY ONE continuation or is a LEAF: one continuation under a goal → the HOP from that goal (`hopForStep`), on the trunk and inside branches alike, in all four layouts; a leaf that is its goal's sole consumer → that goal's FOLD (reading a branch to its end by skips); one continuation under a TACTIC (a broken chain's synthetic `calc`) → the ghost.
